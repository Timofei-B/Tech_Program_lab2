# Исследование уязвимостей OWASP Top 10 в веб-приложениях на Python (Flask)

Программа была проверена на системе Windows 11

Практическая работа демонстрирует наличие, эксплуатацию и методы устранения двух классических уязвимостей из списка **OWASP Top 10 (A03:2021 — Injection)**:
1. **SQL Injection (SQLi)** — внедрение SQL-кода через параметры запроса.
2. **OS Command Injection** — внедрение системных команд операционной системы через параметры утилиты `ping`.

---

## Структура проекта

* `app.py` — уязвимая версия веб-приложения на микрофреймворке Flask.
* `app_fix.py` — пропатченная, безопасная версия веб-приложения.
* `exploit.py` — автоматизированный скрипт на Python, демонстрирующий эксплуатацию уязвимостей с помощью библиотеки `requests`.
* `patch.diff` — файл различий (diff) для наложения патча на уязвимый код.
* `requirements.txt` — список необходимых зависимостей проекта.
* `README.md` — подробная документация по проекту.

## Подробное описание уязвимостей и их эксплуатация

### Уязвимость №1: SQL Injection (SQLi)

* **Описание:** В эндпоинте `/user` параметр `username` принимается из GET-запроса и напрямую конкатенируется в строку SQL-запроса без какой-либо фильтрации или экранирования.
* **Уязвимый код в `app.py`:**
  ```python
  query = f"SELECT * FROM users WHERE username = '{username}'"
  c.execute(query)
  ```
* **Механизм эксплуатации:** 
  Злоумышленник передает специальную строку `Who?' OR '1'='1`, которая ломает логику исходного условия `WHERE`. Запрос трансформируется в конструкцию, которая всегда возвращает истину, позволяя обойти аутентификацию или извлечь конфиденциальные данные (например, секретные флаги).
* **Запуск эксплойта:**
  В отдельном окне терминала выполните скрипт:
  ```bash
  python exploit.py
  ```
  **Ожидаемый ответ сервера:**
  ```text
  Данные пользователя: (1, 'admin', 'super_secret_flag{sqli_success}')
  ```

---

### Уязвимость №2: OS Command Injection

* **Описание:** В эндпоинте `/ping` параметр `host` используется для формирования системной команды `ping`. При вызове функции `subprocess.check_output` с флагом `shell=True` переданный пользователем ввод передается напрямую командной оболочке операционной системы.
* **Уязвимый код в `app.py`:**
  ```python
  command = f"ping -n 1 {host}"
  output = subprocess.check_output(command, shell=True, stderr=subprocess.STDOUT)
  ```
* **Механизм эксплуатации:**
  Используя операторы объединения команд (в Windows — амперсанд `&`; в Unix/Linux — точка с запятой `;`), злоумышленник может дописать произвольные системные команды (например, `whoami`, `dir`), которые будут выполнены интерпретатором ОС с привилегиями запущенного веб-сервера.
* **Пример полезной нагрузки (payload):** `127.0.0.1 & echo HACKED! Current user: & whoami`
* **Ожидаемый ответ сервера:**
  ```text
  Обмен пакетами с 127.0.0.1 по с 32 байтами данных:
  Ответ от 127.0.0.1: число байт=32 время<1мс TTL=128
  ...
  HACKED! Current user:
  desktop-lgr13d\user
  ```

## Устранение уязвимостей (Патчинг)

Для защиты приложения были применены следующие архитектурные и безопасные практики:

1. **Защита от SQL Injection:**
   * Отказ от интерполяции строк в SQL-запросах.
   * Использование **параметризованных запросов** (prepared statements) с передачей параметров в виде кортежа через знак вопроса (`?`), что исключает интерпретацию данных как команд SQL:
     ```python
     query = "SELECT * FROM users WHERE username = ?"
     c.execute(query, (username,))
     ```

2. **Защита от OS Command Injection:**
   * Отключение вызова командной оболочки (`shell=False`).
   * Передача исполняемой программы и её аргументов в виде строгого **списка строк** (`list`), что предотвращает внедрение управляющих символов оболочки (`&`, `;`, `|`):
     ```python
     command = ["ping", "-n", "1", host]
     output = subprocess.check_output(command, shell=False, stderr=subprocess.STDOUT)
     ```
